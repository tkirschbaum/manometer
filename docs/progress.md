### Built

- `spikes/office-spike/`: a throwaway PowerPoint content add-in (plain HTML/JS + Office.js) and a dependency-free
  Node 22 HTTPS server on `https://localhost:3443` using `office-addin-dev-certs`.
  - Shows and logs platform, version, display language, active view and `ActiveViewChanged`, the current slide via
    `SlideRange` (on load, click, `DocumentSelectionChanged`, 1 s polling), per-instance settings (write / read /
    50 kB / save), the §6.6 activation rule (ON / OFF SCREEN) and the §6.5 copy detection.
  - Probes the document-level stores through `PowerPoint.run` (presentation tags, custom document properties,
    custom XML parts), lists shapes and resizes the frame to the full slide, checks `openBrowserWindow`,
    requirement sets and whether Office.js nulls the `history` methods.
  - `localStorage` heartbeat + `BroadcastChannel` to see other live instances (fallbacks for §6.4 and §6.5).
  - Lifecycle, rendering activity (frames per second), keyboard and click logging for the slideshow.
  - On-demand service worker to test whether the add-in can start while the server is unreachable.
  - Central log collection from every instance (`/logs`, `/report.md`, `/logs.ndjson`), so presenter-view and
    preview instances report even when nobody can see them.
- `manifest.xml` (XML add-in-only, `ContentApp`, host `Presentation`, 960×540, `ReadWriteDocument`) generated by
  `make-manifest.mjs`; a tunnel variant for one shared server.
- [`phase0-checklist.md`](phase0-checklist.md): 12 tests, about 60–90 minutes per platform, with `W:`/`M:` answer fields.
- [`phase0-findings.md`](phase0-findings.md): V1–V19 result table covering every **[VERIFY]**, desk research,
  and decision rules D1–D7 so the decisions follow directly from the results.

### Verified here (no PowerPoint in the cloud session)

- Server starts, serves the page, collects logs, renders `/logs` and `/report.md`.
- Manifest parses with `office-addin-manifest info`. Online validation (`office-addin-manifest validate`) needs
  Microsoft's validation service, which this session's network policy blocks; it is checklist step T0.4.
- Smoke test in headless Chromium against a mocked Office.js (kept out of the repo, it only exists to catch bugs
  before the real run): page without Office.js shows a clear state; settings are created on load; the first click
  binds the slide; slideshow view shows ON SCREEN on the bound slide and OFF SCREEN after the slide changes
  (polling and selection event); copy detection reports on load and forks the item on click; two instances see
  each other via `localStorage` and `BroadcastChannel` and flag the shared item id; probes complete even when an
  API is missing; with the service worker registered the page starts while the server is down and the queued log
  is delivered when it comes back. Ran three times, stable.
- The smoke test found one spike bug (a synchronous throw from `PowerPoint.run` stopped the probe sequence); fixed.
